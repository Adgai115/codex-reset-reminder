# 桌面版使用指南

适用于 Electron 桌面版。先安装并登录本机 Codex CLI；提醒器读取当前登录账号的 Usage，当前版本只支持一个 Codex 账号。

## 第一次打开

1. 打开应用，进入“安装与连接”。如果自动找到了 Codex CLI，保留这个路径；没有找到时点“浏览”。
2. 可先点“检查 Codex 连接”确认 Usage 可读，再点“验证连接并开始”。连接中会锁定表单，失败时可修改后重试。
3. 根据需要选择“登录系统时自动启动”。启动到托盘后，应用会在后台检查提醒。
4. 进入卡片管理，等待第一次同步完成。用 Codex Usage 核对数量和到期时间。
5. 打开“提醒设置”，选择桌面弹窗或飞书私聊。桌面弹窗可立即测试；飞书需先完成机器人连接。

如果升级前已有 Codex 卡，管理页会先显示当前 CLI 账号的脱敏邮箱，并要求确认“这是原账号”后绑定旧缓存。无法确定时先切回原 CLI 账号，再点“重新核对账号”；绑定前不会把新账号 Usage 合入旧缓存。没有旧 Codex 卡时，首次成功核对会自动绑定。手动卡不依赖 Codex 账号。

Windows 旧版用户如看到迁移提示，迁移会复制本地数据，并停用旧计划任务以避免重复提醒。选择暂不迁移会退出新版。

## 日常看卡

“可用卡”按到期先后排列；“历史卡”保留已使用、过期和失效记录。卡片编号显示不下时，鼠标悬停可查看完整编号。时间均为电脑本地时区。

- **立即同步 Codex**：只读取 Usage；进行中显示“同步中”，结束后更新列表。失败时继续使用已有缓存，超过 24 小时未完整核对会提示。
- **稍后提醒**：选择 1 天后、3 天后或明天 10:00。仅显示卡片过期前可执行的选项，不改变官方到期时间。延期期间经过的固定节点不会重复提醒。
- **取消延期**：恢复固定的 7 / 3 / 1 天提醒规则，已发送记录仍然保留。
- **新增手动卡 / 编辑**：补充自动同步没有读取到的卡片；需填写未来的到期时间。
- **提醒发送**：每张卡按提前 7 / 3 / 1 天或延期节点，分别显示桌面、飞书等渠道的最近发送结果和时间。“桌面已弹出”表示窗口已创建，“飞书已发送”表示发送接口已确认；都不表示用户已读。旧版已发送记录也会继续显示。
- **失败渠道补发**：首次失败后最多再试 3 次，间隔依次为 1、5、15 分钟。只补发失败渠道，已成功的渠道不重发。可在当前节点点击“重试失败渠道”提前执行下一次尝试；运行中按钮会锁定。达到 4 次总尝试上限后停止，检查渠道设置并等待下一提醒节点。延期、免打扰、到期、已使用、渠道开关和新节点接管仍会阻止不合适的补发。

关闭了全部提醒渠道时，卡片仍会保留，但不会收到提醒。可在“提醒设置”重新开启渠道。

## “使用”按钮分别做什么

| 入口 | 按钮 | 实际行为 |
| --- | --- | --- |
| 管理页的 Codex 卡 | 我已使用 | 记录已在 Codex 中使用过的反馈，等待下次同步核验；此按钮不消耗卡片 |
| 管理页的手动卡 | 标记已使用 | 只更新本地手动卡并停止其后续提醒 |
| 新飞书提醒的 Codex 卡 | 立即使用 | 飞书弹出二次确认后，请求 Codex 正式用卡接口 |
| 历史飞书消息 | 确认使用 / 已使用 | 保留旧语义，只记录使用反馈 |

未核验成功时不会把卡片直接扣减。管理页会显示“等待使用核验”；如果 Codex 确认卡片仍在，会恢复其正常提醒。

## 设置与连接修复

点击“保存设置”后返回管理页；取消或关闭时，如有修改，会询问是否放弃。保存期间不要退出应用。自启设置失败时，提醒配置不会先行保存；配置写入失败会尝试恢复原自启设置。

飞书连接为可选项。展开“飞书连接”，按提示配置应用和接收人；测试私聊成功后才保存连接。更换机器人需要点“重新连接”并确认；连接成功不会覆盖尚未保存的免打扰等修改。

如更新或移动 Codex 后同步失败，在“连接诊断”点击“重新选择 Codex 程序”。验证连接成功后才替换路径，卡片和提醒记录会保留。更换 CLI 账号时，管理页显示原绑定账号与当前账号的脱敏信息，并暂停旧 Codex 卡的同步、提醒、使用反馈和飞书正式用卡。切回原账号后点“重新核对账号”恢复；不能把旧缓存直接绑定给另一个账号。网络或 CLI 故障显示“无法核实”，不会当作换号，也不会显示账号已确认。

账号保护使用 Codex App Server 的 `account/read`。当前本机 CLI 返回 ChatGPT 邮箱，没有提供工作区账号 ID；应用保存带随机本地作用域的邮箱摘要和脱敏显示。若以后协议提供工作区 ID，也会一并核对。仅靠邮箱无法区分同一邮箱下、但当前 CLI 未提供 ID 的不同工作区，遇到这种情况请人工核对 Usage。协议依据见 [Codex App Server 的账号响应结构](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/json/v2/GetAccountResponse.json)。

“测试桌面弹窗”只显示演示卡，不改变真实卡片和提醒记录。“检查新版本”由用户手动触发，不会自动下载安装；正式版用户不会被提示安装预发布版本。

## 收起、退出和离线

- **最小化 / 收起到托盘**：应用仍然运行，继续检查和提醒。点击托盘图标或菜单可以恢复；再次启动快捷方式也会恢复已有窗口。
- **退出应用**：停止本机提醒和飞书按钮监听。需要继续提醒时重新打开应用。
- **Codex 无法核实账号**：已保存的 Codex 卡继续留在本地，但暂停同步、提醒和正式用卡；手动卡继续按设置提醒。恢复连接后点“重新核对账号”。
- **睡眠或关机**：本地程序不能在关机时发送消息；恢复运行后会补查尚未过期的提醒。

macOS、Linux 的托盘、自启和休眠恢复仍需要真实桌面环境验证，当前 CI 主要验证安装包启动与隔离的演示流程。平台限制见 [实际使用验收](platform-qa.md)。

发送超时可能发生在服务端接收消息之后。飞书补发会复用同一提醒节点的幂等键，降低重复消息风险；桌面弹窗和旧公众号通道没有同等的服务端去重能力。进程在发送成功与本地记录写入之间退出时也可能再次尝试，因此无法承诺所有故障下严格只收到一次。收到疑似重复提醒时，先看管理页的节点、渠道和时间，再决定是否重试。
