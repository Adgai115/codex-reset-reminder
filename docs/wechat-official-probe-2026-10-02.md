# 微信官方直连验证（2026-10-02）

## 目的与当前结论

独立验证腾讯微信 ClawBot 协议是否适合重置卡到期提醒，避免 PushPlus 等第三方中转。此次提供开发验证工具，不接入正式提醒调度、不更改已安装版本，也不打进产品安装包。

**在手机实际看到消息前，不把接口成功当作送达；25 小时测试完成前，不承诺长期主动提醒可用。** 无上下文令牌是否可发送、上下文有效期和后台主动推送限制都需要实测。短时间成功不代表 7 / 3 / 1 天到期提醒已具备可靠性。

## 官方依据

- [腾讯微信 ClawBot 接入指南](https://cloud.tencent.com/document/product/1831/137450)：手机微信要求为 8.0.70 或以上，使用扫码绑定。
- [Tencent/openclaw-weixin 协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)：HTTPS JSON、扫码登录、获取消息、文本发送接口及上下文令牌。
- [腾讯扫码实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/auth/login-qr.ts)与[发送实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/api.ts)：用于核对当前请求构造。

腾讯协议文档明确区分客户端行为与服务端契约。文档中的可选字段和客户端允许省略上下文令牌，均不能证明服务端会接受任意主动发送。

工具直接访问协议要求的微信 HTTPS 地址，不调用模型，不部署云端服务。腾讯服务器会接收验证消息文本及协议身份信息；Codex 账号、凭据、数据库和真实卡片不参与验证。

## 启动

在项目目录使用旧版 PowerShell 也可执行：

```powershell
npm run probe:wechat
```

开发用完整模拟窗口（不访问微信）：

```powershell
npm run probe:wechat -- --mock
node scripts/wechat-official/launch.mjs --smoke
```

打开独立验证窗口后，按工具提示获取二维码、用手机微信扫码，必要时在本机窗口输入手机显示的验证码。绑定后，先在手机 ClawBot 会话发送工具指定的验证文字，再从本机窗口明确发起测试。

不要在聊天、提交、截图或日志中粘贴二维码授权链接、验证码、Bot token 或上下文令牌。

## 本地隔离与凭据

| 数据 | 位置与规则 |
| --- | --- |
| 独立 Electron profile | `.git/wechat-official-probe-profile/`，不进入 Git 提交或安装包 |
| 会话 | 该 profile 下的 `session.bin`，使用 Electron `safeStorage` 加密；系统加密不可用时停止保存 |
| 验证记录 | 该 profile 下的 `status.json`，仅记录时间、测试阶段、接口结果及用户确认的可见结果 |
| 二维码 | 本机 QR 编码器生成 SVG data URL，不请求第三方二维码生成站点，不把授权 URL 写入日志 |

`status.json` 不保存原始用户消息、完整身份、二维码值、Bot token、上下文令牌、验证码或原始网络响应。窗口不获得发送任意文案、读取任意文件或操作正式应用的权限。

二维码使用 `qrcode-terminal@0.12.0` 包内的 QR 编码器，属于开发依赖，不新增前端框架或正式运行依赖。该包主许可是 Apache-2.0，其中 `vendor/QRCode` 由 Kazuhiko Arase 编写并标注 MIT；工具仅调用该本地编码器生成图片，不启用终端链接输出。[许可来源](https://github.com/gtanner/qrcode-terminal/blob/master/LICENSE)

工具不读取项目旧 `config.json` / `.state`，也不读取正式 userData 中的配置、SQLite 数据库或加密 Codex 会话。不修改正式配置，不消费真实重置卡，不发送飞书消息。

## 人工验收

所有出站消息使用固定模拟文案。打开窗口、扫码、读取状态和保存凭据均不发送测试消息；真正发送仅来自用户在工具中明确点击或确认安排的测试。

| 阶段 | 操作 | 必须记录的证据 |
| --- | --- | --- |
| 绑定 | 手机扫码，必要时输入验证码 | 本机显示已绑定；不记录授权材料 |
| 入站 | 手机在对应会话发送工具指定验证文字 | 工具捕获对应用户的有效验证消息和上下文；不保存正文 |
| 立即 | 点击发送立即测试 | 接口结果、发送时间、手机实际可见确认 |
| 无上下文 | 明确选择不带上下文令牌发送模拟消息 | 区分接口拒绝、接口接受但不可见、手机可见 |
| 5 分钟 | 用户确认安排一次延迟发送；期间不再发送新的入站消息 | 计划时间、实际发送时间、上下文年龄、手机可见确认 |
| 25 小时 | 用户确认安排一次长时间发送；期间不更新用于此测试的上下文 | 同上；未实际完成时保持待验证 |

5 分钟与 25 小时用于观察会话窗口和主动发送，不是腾讯承诺的有效期。计划任务明确可取消；关闭或退出工具后停止在本机自动执行，重开时不自动补发。休眠、离线或系统调度可能使执行延后，以记录的实际发送时间和距获取上下文的分钟数核对，不承诺精确计时。

`ret: 0` 表示接口接受；它不是手机可见收据。“手机已看到”只能由用户核对对应测试消息后确认。模拟消息附带测试编号，可与本机记录的阶段和发送时间核对，避免把旧消息误认作新测试。

发送超时、断连或无法判断服务端是否接受时，标记结果未知并停止自动重试，避免重复消息。明确失败也不自动发送另一条测试。

## 开发检查

开发测试全部使用隔离 profile、模拟网络和模拟加密依赖；自动化检查不扫码、不调用真实微信接口、不发送真实消息。

需要检查请求构造、官方域名限制、重定向处理、秘密不进入 renderer / 日志 / status、IPC 页面与窗口身份校验、任意文案拒绝、未知发送不重试、取消延迟和重启恢复。

验证工具通过单元测试不能替代手机送达和 25 小时测试。2026-10-03 增加可手动开启的[本机共用通知实验接口](wechat-shared-notifications.md)，供多个 agent 和开发版提醒应用调用；该接口尚不作为长期主动提醒可靠性的证明。
