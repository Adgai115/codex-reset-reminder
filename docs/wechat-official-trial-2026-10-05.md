## 后续实验与结论边界

为区分连接问题和对新会话的要求，需要用户在手机 ClawBot 发送“验证”，由工具确认收到新的入站上下文，再做独立的带上下文测试。新测试成功只能证明当前会话可回复，不能代替旧绑定长闲置发送的手机核对，也不能据此认定长期主动提醒可用。

如继续观察上下文寿命，延迟测试必须冻结取得的上下文，并记录实际发送时刻、上下文年龄及手机收件确认。任何未知结果均停止补发；明确拒绝保持失败。未满足长期主动提醒验收前，不将官方直连渠道整合并发布为可靠到期提醒能力。

[腾讯官方协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md) 区分客户端字段与服务端契约：客户端允许省略上下文，不代表服务端保证接受。文档没有给出可据此承诺的任意长期主动发送保证；25 小时是本项目观察点。

## 诊断与分类修正

后续发送仅将明确非零 `ret` 记为拒绝（`ret=-14` 单列会话失效）；缺少 `ret`、`ret=0` 与非零 `errcode` 冲突或字段类型非法时记为未知，仍停止补发。只保留固定类别、有符号 32 位数值 `businessCode/responseRet/responseErrcode` 和 100–599 的 HTTP 状态，不保存原始响应、错误文字、消息内容或凭据。已有旧记录保持原样，不补填猜测数据，也不因修正分类宣称实验通过。[官方发送实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/api.ts)

验证结果：完整 `npm test` 共 249 项，248 通过、1 项平台跳过、0 失败；Electron 37 模拟窗口烟测通过。数值字段过滤、持久化/恢复、旧记录兼容、发送返回冲突、明确拒绝、未知不补发与 UI 显示均使用隔离数据和模拟依赖检查。本轮没有构建或安装整合版，因为实验门槛未满足。
