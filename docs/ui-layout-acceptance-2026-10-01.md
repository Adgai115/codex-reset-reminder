# 界面布局优化验收

版本：v2.2.2。使用隔离数据库、模拟账号和渠道验证；未消费真实卡或发送测试飞书消息。

## 优化与理由

| 问题 | 改进 | 实际测量 |
| --- | --- | --- |
| 窄窗口操作入口在可见范围外 | 四列：卡片、到期、提醒、操作；状态归入到期列 | 800px 窗口表格从 1060px 缩到 766px，无横向滚动 |
| 页头占用过多空间 | 标题、账号、全局操作对齐；主导航与卡片筛选同一行 | 压力场景列表起点从 242px 降到 145px |
| 每张卡重复展开提醒说明 | 默认保留每渠道结果与时间、查看提醒、失败补发；完整信息放在详情 | 三渠道压力场景行高从 188px 降到 105px |
| 长失败原因只靠悬停提示 | 卡片与记录均可打开完整详情 | 长卡名、完整编号、失败原因尾部可通过键盘读取 |
| 刷新后详情按钮失去键盘焦点 | 保留详情操作焦点；关闭后返回当前列表入口 | 数据变化、补发成功/失败、Escape 期间关闭均通过 |
| 页面配色与控件不一致 | 四页跟随系统深色，统一布局、颜色与焦点样式 | 深浅两种主题、长名称和窄窗口通过 |
| 设置常用内容需要滚动 | 通知和免打扰使用紧凑设置行，保存区固定 | 默认设置在 560×500 完整显示；仅展开详细设置后滚动主内容 |

## 自动验证

- `npm test`：121 项，Windows 120 通过、1 项 Unix 专用检查跳过。
- Chrome 实际模块和模拟 `window.api`：800×480、1180×680，30 字账号名、长卡名、三个渠道、已提醒/重试入口、空列表、记录原因、深色与键盘交互。
- 设置/安装页：12 个深浅主题和布局场景，包括全部设置展开、长路径、连接失败、无效免打扰与保存、飞书连接入口。
- 背景新增同步记录、排序变化后，关闭详情仍返回同一记录；换账号会关闭旧账号详情。长账号名称提供完整悬停提示。
- Windows CI 曾检出关闭详情后下一轮刷新再次丢失焦点；对照旧提交复现卡片和记录入口均变为 `BODY`，修复后同入口在新 DOM 中保留焦点。安装包检查持续覆盖第二轮刷新。
- 可重复的安装包检查：`node scripts/smoke-packaged.mjs --setup`、默认流程、`--p0`、`--accounts`；覆盖原生 renderer/preload、紧凑布局、深浅主题、详情、延期、保存及多账号作用域。

## 验证范围

Windows 本地完整 NSIS 构建、SQLite、包内容和升级元数据校验通过；已打包的首次连接、卡片/设置/模拟提醒、失败补发、多账号流程通过。内置 SQLite 与 Node sidecar 的多账号检查均覆盖账号切换、记录隔离、单账号故障与重启恢复。

Windows 原生用卡二次确认取消、合并提醒、独立延期、重启恢复及实际 90 秒自动收起通过。

多账号后台同步、提醒去重、有限补发和用卡二次确认沿用已验证的业务流程。CI 验证 Windows、macOS、Linux 的安装包和隔离流程；CI 不代替 macOS/Linux 实际桌面、托盘和系统缩放验收。

真实用卡、真实飞书发送与第二账号官方 OAuth 未作为 UI 测试执行。Windows 安装包仍未签名；macOS 包仍未签名、未公证。
