# 三平台实际使用验收

自动构建使用隔离数据与模拟 Codex App Server 检查安装页、官方卡展示、延期、使用反馈、设置页、测试弹窗，以及内置 SQLite 和 Node sidecar 两种模式。还检查新增/编辑接口被拒绝、旧手动记录不展示和不提醒、官方名称和到期时间保持不变、过期卡归档、后台操作刷新、表单错误可见性、设置保存后关闭、后台启动不弹窗及第二实例恢复。模拟程序只提供账号和 Usage 的读取响应；测试不会登录真实 Codex、发送飞书消息或使用重置卡。

`node scripts/smoke-packaged.mjs --p0` 在隔离目录预置模拟官方卡的失败结果，检查账号不可核实时暂停补发、恢复账号后允许重试、失败原因、加载态与成功结果。三平台 CI 均执行此脚本；它不调用真实 Codex 或飞书。

beta.3 增加 1180 / 800 像素的布局检查：页面无横向溢出，卡名、时间、状态和按钮不折行，窄窗口表格内部可横向滚动；长名称与完整发送原因可展开读取，后台刷新保留展开状态。延期选择后直接生效，不再额外弹窗确认。

`node scripts/smoke-packaged.mjs --recovery` 先用缺失的模拟账号响应制造故障，再恢复模拟账号和 Usage 文件；等待真实后台计时器的一分钟重试，不点击刷新。断言账号自动核实、卡片自动更新、成功后重试状态清除且下次同步恢复十五分钟。三平台 CI 均执行；单元测试另用虚拟时间覆盖 1 / 5 / 15 分钟退避、持续失败、并发请求合并、唤醒节流与退出期间的在途任务。

beta.4 精简四个页面的常驻文字。隔离 GUI 检查覆盖：管理页的计划与账号详情默认收起，设置页的诊断和版本默认收起、仍可正常展开，安装页连接帮助收起；提醒弹窗的数量与同步记录收起，测试标题可辨认，卡名和操作保持单行，底部操作完整可见。P0 演示提醒通过延期菜单直接保存并关闭，仍保留错误原因、账号异常和失败重试入口。

以下项目需要在对应操作系统的真实桌面会话中验收。当前只有 Windows 开发机；macOS 和 Linux 尚无可用实机，不能把 CI 通过写成实机通过。

## Windows、macOS、Linux 各做一次

1. 安装包首次启动：进入“安装与连接”；选择已登录的 Codex CLI，点“检查 Codex 连接”，确认 Usage 可读后开始使用。
2. 卡片管理：核对 Codex Usage 的可用数量和到期时间，确认没有新增或编辑卡片入口。用隔离脚本提供的模拟官方卡检查设置/取消延期与使用反馈；名称和官方到期时间应保持不变。
3. 设置：检查本地诊断、飞书配置和按钮监听的状态；测试桌面弹窗，并确认弹窗能关闭。
4. 飞书（仅配置了机器人时）：发送测试私聊，用演示卡检查交互按钮与延期回调。正式用卡必须另行确认，不用于日常验收。
5. 托盘：关闭时可选择收起、退出或取消；收起后仍能从托盘重新打开，退出应用后提醒和监听应停止。设置未保存时，继续编辑和放弃修改两条路径都要验证。
6. 登录自启：启用后重新登录系统，确认应用启动且无第二实例；关闭后重新登录，确认不再启动。
7. 休眠恢复：在演示环境安排到期节点，休眠跨过节点并唤醒，确认只补提醒一次。
8. 升级：退出旧版本，备份用户数据目录，安装新版本；确认卡片、延期和渠道设置保留且无重复提醒。
9. 发送结果：分别触发桌面和飞书演示提醒，核对每张卡、每个节点、每个渠道的结果与时间。飞书显示“已发送”时，不要把它当作对方已读。
10. 失败补发：用测试渠道模拟一次失败，确认只有失败渠道按 1、5、15 分钟补发且最多 3 次；免打扰、延期和新节点覆盖时不发送旧节点。
11. 账号保护：在测试用 CLI 账号之间切换，确认旧卡仍在缓存但不合并新卡、不执行正式用卡；切回原账号并重新核对后恢复。旧数据第一次绑定需明确确认原账号。不要用真实重置卡验证正式用卡按钮。

## 平台关注点

- Windows：旧 PowerShell 版迁移后检查四个计划任务已禁用；若停用失败，新版不应启动提醒。
- macOS：目前未签名或公证；检查 Gatekeeper 放行、自启和托盘行为。正式面向普通用户发布前需要签名与公证。
- Linux：分别安装 AppImage 和 deb；检查桌面环境是否显示托盘图标。不同桌面环境的激活方式可能不同，从托盘菜单打开是回退路径。检查 `~/.config/autostart` 中的应用路径在升级后仍有效。

记录系统版本、桌面环境、安装包版本、Codex CLI 版本、测试时间和失败截图。不要把 App Secret、Codex 登录信息或飞书原始回调写进公开问题单。

Windows 开发机可运行 `node scripts/smoke-packaged.mjs --native-dialogs` 自动检查原生关闭确认；脚本只点击隔离测试进程的按钮。`--background` 可检查后台启动及再次启动恢复窗口，CI 的 sidecar 流程会执行这项检查。可设置 `CODEX_RESET_SMOKE_SCREENSHOTS` 为本机输出目录，留存演示数据截图。
