# 多账号管理验收

版本：v2.2.0。测试数据、配置和 Codex 接口全部隔离；未使用真实重置卡，未发送测试飞书消息。

## 功能

| 操作 | 结果 |
| --- | --- |
| 选择账号 | 立即读取该账号的卡片、同步记录、提醒记录；随后独立刷新 |
| 添加账号 | 官方浏览器授权；独立会话加密保存，不切换 CLI 登录 |
| CLI 换号 | 识别新账号，已有账号继续同步和提醒 |
| 单账号失联 | 独立退避重试，其余账号继续工作；缓存仍可查看和延期 |
| 暂停账号提醒 | 停止该账号发送和补发，保留同步、卡片与记录 |
| 相同官方卡号 | 各自保存本地记录，正式用卡始终请求所属账号 |
| 重启 | 恢复账号列表、加密会话、同步记录与发送记录；不重复发送 |

## 自动验证

| 检查 | 本机结果 |
| --- | --- |
| `npm test` | 95 项：94 通过，1 项 Unix 专用检查在 Windows 跳过 |
| `npm run probe:sqlite` | Electron 37.10.3 内置 SQLite 可用 |
| `node scripts/smoke-packaged.mjs --accounts` | 通过；覆盖账号选择、重复卡号、两种记录、故障隔离和正常退出后的重启恢复 |
| `CODEX_RESET_MONITOR_CORE_MODE=sidecar` 的同项检查 | 通过 |
| 凭据边界 | 系统加密、拒绝不安全存储、登录取消、重新登录身份不符、浏览器会话不被 CLI 覆盖 |
| 用卡边界 | 只使用模拟接口；未保存独立会话的账号无法通过当前 CLI 回退消费 |

三平台 CI 还执行首次安装、卡片与设置页、P0 失败补发、自动恢复、合并提醒、后台启动，以及内置 SQLite/Node sidecar 两种多账号流程。Linux CI 使用隔离的 GNOME Keyring 和 D-Bus 会话。

## 数据兼容与范围

- 升级保留旧卡片、延期、同步历史与提醒历史。只有身份记录的历史账号需独立登录一次；升级无法凭身份哈希重建登录凭据。
- 安装包不包含用户配置、数据库或凭据，旧 PowerShell 路径继续保留。
- Windows 安装包未签名；macOS 未签名、未公证，缺少材料不阻断发布。
- 真实第二账号的浏览器授权、真实飞书送达、正式用卡，以及 macOS/Linux 托盘、自启、休眠仍需实机验收。
