# 桌面版使用指南

适用于 Electron 桌面版。提醒器支持管理多个 Codex 账号：每个账号有自己的卡片、同步记录、提醒记录和登录会话。顶部选择账号即可查看，已添加账号在后台分别同步和提醒。重置卡由官方发放，应用不提供新增或编辑官方卡片。

## 多账号管理

| 操作 | 入口与结果 |
| --- | --- |
| 查看账号 | 顶部账号选择框；切换后立即显示该账号缓存，并在后台刷新 |
| 添加账号 | “账号管理 → 添加账号”，在浏览器完成 Codex 官方登录；不改变 Codex CLI 的当前登录 |
| 获取 CLI 账号 | 自动发现本机当前账号；“获取 Codex 当前账号”可立即核对 |
| 设置账号名称 | 账号管理中输入“工作号”等名称，失去焦点后自动保存 |
| 查看记录 | “同步记录”“提醒记录”分别列出所选账号的核对与发送结果 |
| 暂停账号提醒 | 关闭对应账号的“提醒”开关；其他账号继续提醒，该账号仍可查看和同步 |
| 恢复登录 | 在对应账号行点击“登录”或“重新登录”；登录身份不匹配时保留原会话并拒绝替换 |

切换查看账号不会切换 Codex CLI，也不会停止其他账号的提醒。程序每 30 秒核对 CLI 身份，换号时自动建立或恢复该账号；若页面正在查看原 CLI 账号，会跟随切换。手动选择查看其他账号后，后台不会覆盖该选择。

账号独立登录一次后，可以在重启后继续同步和提醒。升级前保存的历史账号只有身份摘要和缓存，无法从这些信息恢复登录；在“账号管理”中为它登录一次即可启用后台工作，无需切回 CLI。当前 CLI 使用文件登录时会自动保存独立会话；使用系统钥匙串等方式、无法获取可保存会话时，点击“登录”完成独立授权。

每个账号正常每 15 分钟同步；失败或详情缺失只为该账号按 1、5、15 分钟重试，其他账号维持自身计划。登录失效时保留卡片与全部记录，仍可查看、设置或取消延期；手动重新查看提醒会标明“缓存”并禁用正式用卡，新提醒等待该账号恢复登录。

独立会话经 Electron `safeStorage` 使用系统密钥加密保存在用户数据目录中。凭据不进入界面、应用配置或日志。调用 Codex 时使用专用临时 `CODEX_HOME`，请求结束后移除；启动时清理上次异常退出的临时目录。Windows 使用 DPAPI；macOS 使用钥匙串，Linux 需要可用且解锁的系统密钥服务。Linux 的 `basic_text` 回退不用于保存登录：缺少密钥服务时可以查看已缓存账号并读取 CLI 当前账号，独立账号需解锁密钥服务后登录。参见 [Electron 存储保护](https://www.electronjs.org/docs/latest/api/safe-storage)。

## 第一次打开

1. 打开应用，进入“安装与连接”。如果自动找到了 Codex CLI，保留这个路径；没有找到时点“浏览”。
2. 点击“连接并开始”，应用会验证 Usage 并进入管理页。需要排查时展开“连接帮助”检查连接。连接中会锁定表单，失败时可修改后重试。
3. 根据需要选择“登录系统时自动启动”。启动到托盘后，应用会在后台检查提醒。
4. 进入卡片管理，等待第一次同步完成。用 Codex Usage 核对数量和到期时间。
5. 打开“提醒设置”，选择桌面弹窗或飞书私聊。桌面弹窗可立即测试；飞书需先完成机器人连接。

如果升级前已有 Codex 卡，管理页会先显示当前 CLI 账号的脱敏邮箱，并要求确认“这是原账号”后绑定旧缓存。无法确定时先切回原 CLI 账号，再点“重新核对账号”；绑定前不会把新账号 Usage 合入旧缓存。没有旧 Codex 卡时，首次成功核对会自动绑定。旧版手动记录保留在数据库中，不再显示为重置卡，也不再发送提醒。

Windows 旧版用户如看到迁移提示，迁移会复制本地数据，并停用旧计划任务以避免重复提醒。选择暂不迁移会退出新版。

## 日常看卡

“可用卡”按到期先后排列；“已结束”保留已使用、过期和失效的卡片。“已提醒”只筛选仍可用、且已有送达记录的卡片，可以重新查看提醒，并非提醒历史。主列表显示单行卡名、编号尾号、到期时间、状态和提醒结果。同名卡以编号尾号区分，完整编号放在悬停提示中。跨年时间保留年份，时间均为电脑本地时区。窄窗口可左右滚动表格。

顶部保留简短同步状态和所选账号；同步时间与数量只属于这个账号。展开可查看核对时间。账号无法识别或连接失败时只暂停该账号的正式用卡与发送，保留已缓存的卡片。

- **自动同步**：启动即核对账号和 Usage，之后每 15 分钟刷新，电脑唤醒后自动核对。管理页显示下次同步时间；收起到托盘后照常运行。失败或详情不完整时，依次等待 1、5、15 分钟重试；持续故障保持 15 分钟间隔，成功后恢复正常周期。已有缓存保留，超过 24 小时未完整核对会提示。右上角“刷新”可提前执行，多个请求合并，不用重复点击。
- **稍后提醒**：直接选择 1 天后、3 天后或明天 10:00，选择即生效。仅显示卡片过期前可执行的选项，不改变官方到期时间。延期期间经过的固定节点不会重复提醒。
- **取消延期**：在“已延期”菜单选择“取消延期”，恢复固定的 7 / 3 / 1 天提醒规则，已发送记录仍然保留。
- **提醒发送**：列表显示最近节点各渠道的状态、时间和下次重试时间；失败原因、尝试次数和全部节点在“详情”中，也可悬停查看当前失败原因。“桌面已弹出”表示窗口已创建，“飞书已发送”表示发送接口已确认；都不表示用户已读。旧版已发送记录也会继续显示。
- **已提醒**：已发送且卡片仍可用的提醒会保留在“已提醒”筛选中。点“查看提醒”或托盘“已提醒 N 张”可重新打开，不会再次发送消息。关闭弹窗或重启应用不会清除记录；官方确认使用、失效或到期后自动消失。延期后暂时隐藏，延期提醒送达后重新出现。
- **合并弹窗**：同轮多张卡共用一个窗口，一次显示一张，左右按钮切换；窗口显示已核对账号、卡名、编号尾号、到期时间和剩余时间，无需滚动。每张卡可独立延期。点击“立即重置”会显示账号和卡片的二次确认，确认后才向 Codex 发起正式用卡请求。窗口 90 秒后自动收起；重启不重复弹出已发送节点。测试弹窗不能正式用卡；账号无法核实时，正式弹窗会收起。
- **失败渠道补发**：首次失败后最多再试 3 次，间隔依次为 1、5、15 分钟。只补发失败渠道，已成功的渠道不重发。可在当前节点点击“重试失败渠道”提前执行下一次尝试；运行中按钮会锁定。达到 4 次总尝试上限后停止，检查渠道设置并等待下一提醒节点。延期、免打扰、到期、已使用、渠道开关和新节点接管仍会阻止不合适的补发。

关闭了全部提醒渠道时，卡片仍会保留，但不会收到提醒。可在“提醒设置”重新开启渠道。

## 立即重置

| 入口 | 按钮 | 实际行为 |
| --- | --- | --- |
| 桌面提醒的 Codex 卡 | 立即重置 | 本机二次确认后，请求 Codex 正式用卡接口 |
| 新飞书提醒的 Codex 卡 | 立即重置 | 飞书二次确认后，请求同一正式用卡接口 |
| 历史飞书消息 | 确认使用 / 已使用 | 保留旧语义，只记录使用反馈 |

平时只需在 Codex 中正常使用，后台同步会自动更新可用列表，无需手动报告。自动同步和恢复连接不会消费重置卡。正式用卡请求结果不明确时，应用保留同一操作标识，避免再次点击生成另一笔请求；先核对 Codex 的实际状态。

## 设置与连接修复

设置页默认展开通知渠道和免打扰；飞书连接、更多设置、连接诊断和关于按需展开。点击“保存”后返回管理页；取消或关闭时，如有修改，会询问是否放弃。保存期间不要退出应用。自启设置失败时，提醒配置不会先行保存；配置写入失败会尝试恢复原自启设置。

飞书连接为可选项。展开“飞书连接”，按提示配置应用和接收人；测试私聊成功后才保存连接。更换机器人需要点“重新连接”并确认；连接成功不会覆盖尚未保存的免打扰等修改。

如更新或移动 Codex 后同步失败，展开“连接诊断”，点击“选择 Codex 程序”。验证连接成功后才替换路径，卡片和提醒记录会保留。更换 CLI 账号时会识别新账号；已有账号仍在账号列表中，各自使用独立会话运行。旧缓存首次绑定仍需确认原账号。网络或 CLI 故障不会当作换号，也不会删除记录。

连接检查与卡片详情是两个不同结果。Codex 可以返回可用数量，却暂不返回逐卡编号和到期时间；此时设置页会显示“官方暂未提供逐卡到期详情”，管理页保留已有卡片并自动重试。应用不能从数量推断到期时间，也不会把数量变化当作某一张卡已使用。协议允许详情为 `null` 或少于可用数量，见 [Codex 官方响应结构](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/json/v2/GetAccountRateLimitsResponse.json)。

账号识别使用 Codex App Server 的 `account/read`。数据库保存随机本地作用域、身份摘要和脱敏显示；登录凭据另行加密保存。工作区 ID 可用时优先用它匹配账号。身份不明确时不会混合已有缓存。不同账号即使返回相同官方卡号，也使用不同本地记录；正式用卡向该账号的会话发送原官方卡号。协议依据见 [Codex App Server 的账号响应结构](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/json/v2/GetAccountResponse.json)。

“测试提醒”只显示演示卡，不改变真实卡片和提醒记录，也不能正式用卡。Windows 安装版在“关于 → 检查更新”发现新版本后，可点“下载更新”；下载和校验完成，再点“立即升级”并确认。应用会退出，在原安装位置升级后重新打开，用户配置和卡片数据仍在独立的用户数据目录。下载失败可重试，或打开发布页手动下载。正常退出应用不会自行安装已下载的更新。正式版用户不会被提示安装预发布版本。当前 2.0.2 及更早版本没有内置下载功能，首次升级到包含此功能的版本仍需手动运行一次新版安装包；之后才能使用应用内升级。macOS 和 Linux 仍通过发布页获取安装包。

## 收起、退出和离线

- **最小化 / 收起到托盘**：应用仍然运行，继续检查和提醒。点击托盘图标或菜单可以恢复；再次启动快捷方式也会恢复已有窗口。
- **退出应用**：停止本机提醒和飞书按钮监听。需要继续提醒时重新打开应用。
- **某个账号无法连接**：保留该账号的卡片和记录，后台自动重试；其他已连接账号继续运行。需要重新登录时从账号管理进入。
- **睡眠或关机**：本地程序不能在关机时发送消息；恢复运行后会补查尚未过期的提醒。

macOS、Linux 的托盘、自启和休眠恢复仍需要真实桌面环境验证，当前 CI 主要验证安装包启动与隔离的演示流程。平台限制见 [实际使用验收](platform-qa.md)。

发送超时可能发生在服务端接收消息之后。飞书补发会复用同一提醒节点的幂等键，降低重复消息风险；桌面弹窗和旧公众号通道没有同等的服务端去重能力。进程在发送成功与本地记录写入之间退出时也可能再次尝试，因此无法承诺所有故障下严格只收到一次。收到疑似重复提醒时，先看管理页的节点、渠道和时间，再决定是否重试。
