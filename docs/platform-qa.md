# 三平台实际使用验收

自动构建使用隔离的演示数据检查安装页、卡片管理、加卡、延期、标记已使用、设置页、测试弹窗，以及内置 SQLite 和 Node sidecar 两种模式。还检查过期卡归档、后台操作刷新、表单错误可见性、设置保存后关闭、后台启动不弹窗及第二实例恢复。它不会登录真实 Codex，也不会发送飞书消息或使用重置卡。

以下项目需要在对应操作系统的真实桌面会话中验收。当前只有 Windows 开发机；macOS 和 Linux 尚无可用实机，不能把 CI 通过写成实机通过。

## Windows、macOS、Linux 各做一次

1. 安装包首次启动：进入“安装与连接”；选择已登录的 Codex CLI，点“检查 Codex 连接”，确认 Usage 可读后开始使用。
2. 卡片管理：核对 Codex Usage 的可用数量和到期时间；新增一张手动演示卡，设置、取消延期，再标记已使用。
3. 设置：检查本地诊断、飞书配置和按钮监听的状态；测试桌面弹窗，并确认弹窗能关闭。
4. 飞书（仅配置了机器人时）：发送测试私聊，用演示卡检查交互按钮与延期回调。正式用卡必须另行确认，不用于日常验收。
5. 托盘：关闭时可选择收起、退出或取消；收起后仍能从托盘重新打开，退出应用后提醒和监听应停止。设置未保存时，继续编辑和放弃修改两条路径都要验证。
6. 登录自启：启用后重新登录系统，确认应用启动且无第二实例；关闭后重新登录，确认不再启动。
7. 休眠恢复：在演示环境安排到期节点，休眠跨过节点并唤醒，确认只补提醒一次。
8. 升级：退出旧版本，备份用户数据目录，安装新版本；确认卡片、延期和渠道设置保留且无重复提醒。

## 平台关注点

- Windows：旧 PowerShell 版迁移后检查四个计划任务已禁用；若停用失败，新版不应启动提醒。
- macOS：目前未签名或公证；检查 Gatekeeper 放行、自启和托盘行为。正式面向普通用户发布前需要签名与公证。
- Linux：分别安装 AppImage 和 deb；检查桌面环境是否显示托盘图标。不同桌面环境的激活方式可能不同，从托盘菜单打开是回退路径。检查 `~/.config/autostart` 中的应用路径在升级后仍有效。

记录系统版本、桌面环境、安装包版本、Codex CLI 版本、测试时间和失败截图。不要把 App Secret、Codex 登录信息或飞书原始回调写进公开问题单。

Windows 开发机可运行 `node scripts/smoke-packaged.mjs --native-dialogs` 自动检查原生关闭确认；脚本只点击隔离测试进程的按钮。`--background` 可检查后台启动及再次启动恢复窗口，CI 的 sidecar 流程会执行这项检查。可设置 `CODEX_RESET_SMOKE_SCREENSHOTS` 为本机输出目录，留存演示数据截图。
