# 可靠性与多账号优化验收

版本：v2.2.1。测试使用临时数据库、模拟账号和渠道；未消费真实卡、发送测试飞书消息或修改正式配置。

## 问题、理由与实现

| 实际问题与证据 | 用户影响 | 优化 |
| --- | --- | --- |
| 选择 A、CLI 为 B 时，手动核对原先未传作用域 | 核对和提示属于另一个账号 | 核对所选账号；获取 CLI 当前账号保留独立入口 |
| 两个检查等待身份核对后，可发送同一渠道两次；期间延期仍发旧消息 | 重复或不合时宜的提醒 | 核对后复查卡片、延期、开关、免打扰、节点和重试条件，再连续占用渠道；使用最新配置 |
| 第一账号预核对挂起时，后续账号无法发送 | 慢连接拖延其他账号 | 每账号独立执行使用核验、预核对与发送；已知账号同步与 CLI 发现同时推进 |
| 两账号总览执行四次会话检查 | 账号增多后重复 I/O 放大 | 共享配置、卡片与会话检查结果；两账号只检查两次 |
| 脱敏邮箱或昵称重名 | 难以区分提醒和确认的归属 | 仅重名时追加稳定账号尾号；管理与提醒一致 |
| 并发登录创建两个会话，取消后的旧完成回调可覆盖新登录 | 授权状态和列表不可靠 | 提前占用登录位置，隔离旧回调，保存前检查取消状态，保存成功后才登记身份 |
| sidecar 丢失用卡请求标志，弹窗将发送前拦截描述为结果不明 | 无法判断是否已请求用卡 | 保留公开错误分类和请求标志，区分未发起与结果未确认 |
| CLI 不存在时关闭等待不到 exit 事件 | 清理和退出拖延 | 处理 close、stdin 错误；关闭通知只执行一次 |
| 已下载更新重查或安装器启动失败后丢失升级入口 | 重复下载或无法重试 | 同版重查、离线检查及启动失败保留已校验下载；新版本仍要求重新校验 |
| 保存账号时输入仍可修改，忙碌期间动作被忽略 | 修改看起来成功但未保存 | 保存期间锁定账号输入，失败加载真实状态；缓存和暂停提示按实际状态显示 |

## 自动验证

- `npm test`：121 项，Windows 120 通过、1 项 Unix 专用检查跳过。
- `npm run probe:sqlite`：Electron 37.10.3 / Node 22.21.1 内置 SQLite 可用；兼容 sidecar 使用 Node 24。
- 多账号：慢预核对未放行时其他账号已显示模拟提醒；CLI 发现未完成时已知账号已开始同步；总览两次会话检查及一致唯一标签。
- 发送：并发身份核对只发送一次；核对期间延期或停用渠道时发送次数为零；原有补发、免打扰、重启恢复、幂等与确认继续验证。
- 登录：并发、旧回调取消、在途身份读取取消、排队保存取消、保存失败不登记、用卡后保存失败保留请求标志。
- 更新：同版及离线重查、更高版本重新下载、安装器同步及异步启动失败。
- Chrome 隔离 DOM：核对带所选作用域；四个账号输入保存期间均锁定；重查仍显示立即升级；升级期间禁止重查。
- Windows 模拟 CLI 并发日志：修复前 24 个进程有 13 个异常退出；日志互斥后 24 个全部成功、720 个响应齐全，持续测试覆盖 16 个进程和 320 条记录。

## 限制

- Windows 未签名；macOS 未签名、未公证，缺少材料不阻断发布。
- 真实第二账号浏览器授权、正式用卡、真实飞书送达及 macOS/Linux 实机托盘、自启、休眠仍未验证。
- 每轮在所有账号链结束后重排下一轮；外部消息被接收后、本地尚未记账的崩溃仍无法保证严格一次送达。
