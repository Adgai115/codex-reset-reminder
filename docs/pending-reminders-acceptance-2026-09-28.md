# 待处理与合并提醒验收（2.0.0-beta.5）

## 完成范围

- 已发送且官方卡仍可用的提醒保留“待处理”。复用现有 SQLite 发送记录，无新增状态副本；兼容旧版记录，关闭弹窗和重启不会丢失。
- 管理页增加按需出现的“待处理”筛选。点击卡片的“待处理”可重新查看，托盘支持一次查看全部；重新查看不会写入新的发送次数或调用外部消息渠道。
- 同轮固定节点与延期节点共用一个桌面弹窗，按到期先后排序；相同卡合并，旧节点不能覆盖新节点。每张卡独立延期，成功后仅移除对应卡。
- 弹窗 90 秒后自动收起，待处理继续保留。重启不会自动重复弹出已发送节点，新的 7 / 3 / 1 天节点照常执行。多卡列表超过窗口容量时内部滚动。
- 官方使用或失效、到期、延期会自动更新待处理及在途弹窗；账号不一致或无法核实时收起正式弹窗，恢复原账号后可重新查看。演示窗口独立隔离。
- 合并只改变桌面展示，各卡各渠道的发送状态、有限补发、延期、免打扰、去重与账号保护继续独立生效。等待其他渠道期间的用卡、延期或渠道关闭，会在弹窗提交前再次核对。

“待处理”表示卡片尚未处理，不是消息已读/未读。打开 Codex 不等于正式用卡，本地使用反馈也需要官方核实。连接自动修复与日常自动备份仍是后续候选项。
